PlacementPredict — Machine Learning System Report

Predicting student placement outcomes · supervised classification · data → model → serve → monitor

1 · Executive summary

PlacementPredict answers a single question: will this student be placed? A student profile of ~30 inputs is transformed by a frozen pre-processing pipeline, scored by a trained classifier, and returned with a probability in a few milliseconds. This report walks the whole machine-learning lifecycle in plain language:

  • {{ '{:,}'.format(summary['rows']) }} student records — grades, skills, experience, demographics;
  • one reproducible pre-processing pipeline (impute → scale → encode) reused at serve time;
  • four supervised models compared on the same untouched hold-out set;
  • a live JSON endpoint /api/predict plus an interactive form;
  • an unsupervised exploration layer — segments, structure and outliers.

What kind of learning is this? Supervised classification — labels exist (Placed / Not Placed) and the model learns the mapping from profile to outcome. It is not unsupervised (no label discovery) and not reinforcement learning (no agent, no actions, no reward). Clustering in M4 is used only to explore the same data.
Tracing one prediction: HTTP POST → feature lookup → pipeline.transform() → model.predict_proba() → JSON response. Batch prediction is the identical path executed on many rows — one code path, so single and batch scoring can never disagree.
The training–serving boundary. The bug that breaks the most production systems is training-serving skew: features computed differently at serve time than at train time. Feature stores exist to keep one canonical definition of each feature. Here the fitted pipeline.pkl is that single definition — fit once on training data, then reused verbatim everywhere.

Course scope: this system owns classical ML and ML engineering (M1–M4). Deep learning moves to DLAC, generative models to GALE, and LLMs to NLPL.

3 · Data & exploratory analysis (M1)

The dataset holds {{ '{:,}'.format(summary['rows']) }} students and {{ summary['columns'] }} attributes. {{ '{:,}'.format(summary['nulls']) }} cells are missing (five skill columns) and are handled in preprocessing. The target is imbalanced about 2:1 toward placed students — which is why F1 and AUC, not accuracy alone, decide the winner.

Insight: CGPA, aptitude and coding scores cleanly separate placed from not-placed students. Semester grades are strongly correlated with each other and with CGPA — the model leans on a compact set of academic signals rather than eight redundant columns.

4 · Data preparation pipeline (M1)

  • Clean — drop StudentID, IsAnomaly and Salary Package (salary exists only for placed students — label leakage).
  • Impute — median for numerics, most-frequent for categories; ~{{ '{:,}'.format(summary['nulls']) }} missing cells repaired without dropping rows.
  • Scale — StandardScaler so gradient descent in M2 converges.
  • Encode — one-hot for six categorical columns, ordinal for CollegeTier (Tier3→Tier1) and CGPA_Tier (Low→Mid→High).
  • Split & freeze — stratified 80/20, seed 42; the fitted transformer is pickled as pipeline.pkl.

5 · Linear models (M2)

Regularisation first. Ridge (L2) shrinks weights smoothly, lasso (L1) drives weak weights to exactly zero, elastic net combines both. The geometry explains sparsity: the loss contour meets the L1 diamond at a corner, and a corner means a zero weight.

Logistic regression computes P(placed) = σ(w·x + b): a hyperplane decision boundary plus a sigmoid, trained by gradient descent on cross-entropy with ridge regularisation. Coefficients are log-odds, so every score can be explained. Scaling matters for gradient descent — not for the trees in M3.

Categorical features & missing values are covered in the same pipeline: one-hot encoding for unordered categories, ordinal for ordered ones, target and embedding encodings noted as advanced alternatives; deletion, mean/median, model-based imputation and missingness flags compared — median/most-frequent is what production uses here.

6 · Tree-based models (M3)

Decision trees split greedily on Gini impurity and stop at depth/leaf limits; cost-complexity pruning trims branches whose removal barely changes error. One deep tree overfits — the classic bias–variance curve below.

Random forests bag bootstrap samples with feature subsampling to cut variance, and give an out-of-bag error for free. Boosting builds trees sequentially, each fitting the residual gradient of the loss; histogram-based learners with leaf-wise growth (XGBoost / LightGBM, and sklearn's HistGradientBoosting used here) are the modern workhorses on tabular data.

Why trees win on tabular data: no scaling, native handling of missing values and mixed types, cheap tuning, and non-linear interactions for free. Neural networks win on images, text and audio — that is DLAC/NLPL territory.

8 · Serving the prediction (M1)

POST /api/predict→Feature lookup →pipeline.transform()→ predict_proba()→JSON
  • /prediction — interactive form with a live result card;
  • /api/predict — JSON in / JSON out for other systems;
  • /api/health — artifact state and metrics for monitoring;
  • /report/export — this report as a standalone HTML file.

The frozen pipeline means the transform at serve time is byte-for-byte the transform used in training — the practical defence against training–serving skew.

9 · Unsupervised learning (M4)

Clustering finds structure without labels: three student segments appear in k-means, DBSCAN and isolation forest flag unusual profiles as outliers, and PCA compresses the semester-grade block into a couple of components. Segment labels can even be fed back as features into the supervised model — a common production pattern.

10 · Conclusions, limitations & reproduction

  • Academic performance dominates placement outcomes; skills (aptitude, coding, interviews) add signal.
  • Predictions are a decision aid — they cannot capture company demand, interview luck or market swings.
  • The ~2:1 class imbalance means accuracy alone would be misleading; F1 and AUC are tracked instead.
  • Retraining on fresh cohorts each semester keeps the model honest as profiles drift.
