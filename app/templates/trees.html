M3 · Supervised learning

Tree-based models

Decision trees, pruning, bagging, boosting and the modern industrial workhorses — the family that routinely wins on tabular data.

Decision trees — greedy top-down

  • Split at the root: pick the feature + threshold that most reduces impurity.
  • Gini = 1 − Σpᵢ² · Entropy = −Σpᵢ·log₂pᵢ — both peak at 0.5 for a 50/50 mix.
  • Regression trees minimise MSE instead of impurity.
  • Stop when max depth is reached, a leaf is pure, or min_samples_leaf is hit.
  • Each leaf predicts the majority class / mean of its samples.

Gini and entropy usually give near-identical trees — Gini is cheaper (no logarithm).

Pruning — the bias/variance lever

  • Pre-pruning — cap max_depth, min_samples_split, min_samples_leaf. Cheap; risks stopping too early.
  • Post-pruning (cost-complexity, CCP) — grow full, then cut branches that barely reduce Rα(T) = R(T) + α·|T|. α tunes leaf count.
  • Read: deep trees → low bias, high variance; shallow trees → high bias, low variance.

Random forest — feature importance

Random forests — bagging + feature subsampling

BaggingBootstrap samples (sample with replacement) → many deep trees, each seeing different data.
Feature subsamplingAt each split only √d features are considered — decorrelates the trees.
Out-of-bag error~37% of rows are left out of each bootstrap → a free validation set, no CV needed.
Variance-reduction argument: averaging n uncorrelated estimators divides variance by n. Trees are highly correlated, so random features + random samples push correlation down — the forest's error falls while a single tree's does not. Bias stays roughly the bag's bias.

Boosting — learning from mistakes

AdaBoost (intuition)

Train a weak learner, raise the weight of the rows it got wrong, fit the next learner on the reweighted data, repeat. Final prediction = weighted vote. Each round fixes the previous round's errors.

Gradient boosting = functional gradient descent

Instead of reweighting rows, fit the next small tree to the negative gradient of the loss — the direction that reduces loss fastest. F(x) ← F(x) + η·h(x), shrinking with a learning rate η.

XGBoostSplit finding with sorted/quantile sketches, second-order (Hessian) gradients, L1/L2 leaf regularisation, column subsampling.
LightGBMHistogram binning + leaf-wise growth (grow the leaf with the largest loss gain) → much faster on large data.
Heresklearn's HistGradientBoostingClassifier — the same histogram-based idea, no extra install.

The Kaggle reality: on structured/tabular data, gradient-boosted trees beat neural networks in most public competitions — they need no GPU, no embedding of inputs, handle mixed types and missing values natively, and are cheap to retune. Deep learning wins on unstructured data (images, text, audio) — covered downstream in DLAC / NLPL.
